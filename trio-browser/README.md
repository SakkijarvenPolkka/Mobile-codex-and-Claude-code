# Trio — AI 에이전트가 떠다니는 크로뮴 브라우저

Trio는 크로뮴 엔진 위에 만든 브라우저입니다. **Claude · Gemini · ChatGPT** 세 에이전트가 기본으로 들어 있고,
브라우저 위를 떠다니는 별도 창(데스크톱) / 떠 있는 패널과 버블(안드로이드)로 열립니다.

- **로그인해야 사용**: 각 에이전트는 해당 회사의 **공식 로그인 페이지**에서 직접 로그인해야 잠금이 풀립니다.
  로그인 전에는 잠금 화면만 보이고, 서비스의 채팅 화면은 아예 불러오지 않습니다. Trio는 비밀번호를 보거나 저장하지 않으며,
  로그인 여부는 브라우저의 쿠키와 주소로만 판단합니다.
- **검색과 함께**: 주소창에서 `@claude 질문`, `@gemini 질문`, `@chatgpt 질문`, `@모두 질문`으로 바로 묻고,
  검색 결과 페이지에서는 "AI로 검색" 버튼으로 그 검색을 에이전트에게 넘깁니다. 주소창 추천 목록에도 "○○에게 묻기"가 나옵니다.
- **방문 기록 분석**: 방문 기록을 **기기 안에서** 요약(자주 가는 사이트, 시간대·요일 패턴, 세션, 자주 검색한 검색어 등)한 뒤,
  보낼 내용을 그대로 보여 주는 **미리보기에서 확인·수정**하고 에이전트 입력창에 넣습니다. 은행·결제·의료·성인·로그인·메일·내부망
  사이트는 기본적으로 빠지고, 주소의 검색어 외 쿼리와 토큰처럼 보이는 경로는 지워집니다.
- **페이지와 함께**: 페이지 요약, 페이지에 질문, 선택한 글 설명·번역. 입력란 값·비밀번호·숨긴 글·편집 중인 글은 읽지 않습니다.
- **자동 전송 없음**: Trio는 에이전트 입력창에 글을 **넣기만** 하고, 전송은 사용자가 직접 누릅니다. 에이전트의 답변을 읽거나
  저장하지 않고, 에이전트가 브라우저를 조작하지도 않습니다.

> Trio는 독립적으로 만든 브라우저이며 Anthropic, Google, OpenAI와 제휴하거나 승인을 받은 제품이 아닙니다.
> Claude, Gemini, ChatGPT는 각 회사의 상표입니다. 앱에는 각 회사의 로고 대신 글자 모노그램만 씁니다.

## 구성

```
trio-browser/
  shared/     두 플랫폼이 함께 쓰는 데이터와 스크립트
              providers.json(에이전트 정의), search-engines.json, privacy-rules.json, prompts.json,
              site-suffixes.json(IANA 최상위 도메인), inject/(페이지 글 추출, 입력창 찾기), test-vectors/
  desktop/    Windows·macOS·Linux 앱 (Electron 45 = Chromium 156)
  android/    안드로이드 앱 (Kotlin, Jetpack Compose, 시스템 WebView = Chromium)
```

두 앱의 핵심 로직(주소창 입력 판별, 검색어 인식, 개인정보 필터, 방문 기록 통계·요약, 프롬프트, 로그인 판정)은
같은 규칙을 따릅니다. 데스크톱 JavaScript 구현(`desktop/src/core`)이 기준이고, 안드로이드 Kotlin 구현(`android/core`)은
`shared/test-vectors`의 같은 테스트 벡터와 골든 출력(통계 5종, 요약 20종, 프롬프트 14종)을 JVM과 안드로이드 기기 양쪽에서
**글자 하나까지 똑같이** 재현해야 통과합니다.

설계 문서: [`docs/superpowers/specs/2026-11-26-trio-browser-design.md`](../docs/superpowers/specs/2026-11-26-trio-browser-design.md),
데스크톱 UI 명세: [`docs/superpowers/specs/2026-11-26-trio-desktop-ui.md`](../docs/superpowers/specs/2026-11-26-trio-desktop-ui.md).

## 데스크톱

### 실행과 빌드

Node.js 22 이상이 필요합니다.

```bash
cd trio-browser/desktop
npm install
npm start
```

```bash
npm run dist:linux      # dist/ 에 AppImage, tar.gz
```

`package.json`의 `build` 항목에 Windows(nsis, zip)와 macOS(dmg, zip) 대상도 설정되어 있습니다. 각 운영체제에서
`npx electron-builder --win` / `--mac`으로 만듭니다(이 저장소의 빌드 환경에서는 Linux 패키지만 만들어 검증했습니다).

### 사용법

| 동작 | 방법 |
|---|---|
| 에이전트 창 열기/숨기기 | 도구 모음의 C·G·GPT 버튼, 떠 있는 독, `Ctrl+Shift+1/2/3` |
| 바로 묻기 | 주소창에 `@claude …`, `@gemini …`, `@chatgpt …`(한글 `@클로드`, `@제미나이`, `@챗지피티`도 가능) |
| 모두에게 묻기 | `@all …` / `@모두 …` 또는 `Ctrl+Shift+A` — 세 창이 나란히 배치됩니다 |
| 검색을 AI로 | 검색 결과 페이지에서 주소창 오른쪽 "AI로 검색" |
| 페이지 요약·질문, 선택 영역 설명·번역 | 에이전트 창의 빠른 작업, 또는 페이지 오른쪽 클릭 메뉴 |
| 방문 기록 분석 | `Ctrl+Shift+Y`, 메뉴 › 방문 기록 분석, 방문 기록 페이지의 "AI로 분석" |
| 에이전트 창 고정 | 창 머리글의 핀(모든 앱 위에 고정) |

에이전트 창은 머리글을 끌어 옮기고 오른쪽 아래 모서리로 크기를 바꿉니다. 위치와 크기는 기억됩니다.
일반 브라우저 기능(탭, 북마크·북마크바, 방문 기록, 다운로드, 페이지 내 찾기, 확대/축소, 인쇄, 사생활 보호 창, 사이트 권한,
세션 복원, 밝은/어두운 테마, 한국어/영어)과 크롬과 같은 단축키를 지원합니다. 사생활 보호 창에서는 에이전트를 쓸 수 없고
기록이 남지 않습니다.

### 테스트

```bash
npm run test:unit   # 핵심 로직·저장소·IPC 계약·문자열 (226개)
npm run test:e2e    # Playwright로 실제 앱을 띄워 브라우저 기능·에이전트 흐름·보안 회귀를 검사 (35개, 모의 Claude/Gemini/ChatGPT 서버 사용)
npm run typecheck
```

E2E 테스트는 화면이 없으면 Xvfb(+openbox)에서 실행되고, 화면 캡처를 `test/e2e/__screenshots__/`에 남깁니다.

## 안드로이드

Android 9(API 28) 이상. 엔진은 기기의 Android System WebView(크로뮴)입니다.

```bash
cd trio-browser/android
./gradlew :core:test :app:testDebugUnitTest   # Kotlin 핵심 로직(벡터·골든), Robolectric 테스트
./gradlew :app:connectedDebugAndroidTest      # 연결된 기기·에뮬레이터에서 핵심 로직 전체, 묻기 흐름, 로그인한 상태의 흐름을 다시 검사
./gradlew :app:assembleRelease                # app/build/outputs/apk/release/app-release.apk (디버그 키 서명)
```

JDK 17 이상, Android SDK(platform 37.1, build-tools 37)가 필요하며 `local.properties`에 `sdk.dir`을 지정합니다.
JVM에서 도는 테스트 65개(Kotlin 핵심 로직 12개, 앱 53개: Robolectric과 주소창·패널 배치 규칙)와 기기에서 도는 테스트 17개가 있습니다.
안드로이드의 정규식 엔진(ICU)은 JVM과 문법이 달라서(예: `(?U)`를 받지 않음) JVM 테스트만으로는 기기에서의 동작을 보장할 수 없으므로,
벡터·골든 전체를 기기에서도 돌리고, 핵심 로직과 앱의 모든 정규식에 ICU가 거부하는 문법이 들어가지 않았는지도 검사합니다.
로그인한 상태의 흐름은 테스트가 띄우는 로컬 모의 공급사로 실제 WebView에서 검사합니다: 앱을 켠 직후의 첫 질문이 입력창에 들어가는지,
WebView 렌더러가 죽어도 앱이 계속 도는지, 제목을 가린 페이지의 요약, 답변 속 링크가 브라우저 탭으로 열리는지.
Android 11 에뮬레이터(WebView 83)에 릴리스 APK를 설치해 실행·검색 인식·버블·에이전트 잠금 화면, 그리고 주소창·추천 목록·메뉴·
"이 검색을 AI로"에서 에이전트에게 묻기까지 확인했습니다.

화면 구성: 위쪽 주소창(누르면 주소 전체가 선택되어 바로 검색어나 `@claude 질문`을 입력, 입력 중 추천 목록과 "○○에게 묻기"),
가운데 웹 페이지, 아래쪽 뒤로·앞으로·새 탭·탭 목록·메뉴(메뉴 › 모두에게 묻기는 주소창에 `@all `을 넣습니다).
오른쪽 아래의 **떠 있는 버블**을 누르면 세 에이전트가 펼쳐지고, 고르면 **떠 있는 패널**이 열립니다. 패널은 머리글을 끌어
옮기고 오른쪽 아래 손잡이로 크기를 바꾸며, 회전·분할 화면·키보드로 화면이 바뀌면 화면 안에 맞춰집니다. 로그인 전에는 잠금 화면,
로그인 중에는 공식 로그인 페이지, 로그인 후에는 채팅 화면과 빠른 작업(페이지 요약, 페이지에 질문, 선택 영역 설명·번역, 이 검색을 AI로,
방문 기록 분석)이 나옵니다. 로그인 창("Google로 계속하기" 등)은 패널 안에 주소와 함께 열리고, 답변 속 링크는 브라우저 탭으로 열립니다.
WebView 렌더러가 메모리 부족 등으로 멈추면 에이전트 화면과 탭을 새로 만들어(보이는 탭만 바로 다시 불러옴) 앱은 계속 실행되고,
글자 크기·언어를 바꾸거나 백그라운드에서 앱이 정리되어도 열린 탭의 주소는 남습니다.

## 알려진 제한

- **실제 계정 로그인은 이 저장소의 자동 테스트로 검증하지 못했습니다**(테스트용 계정 없음). 로그인 흐름, 입력창 채우기,
  기록 분석은 같은 구조의 모의 서비스로 검증했고, 실제 세 서비스는 로그인 페이지가 에이전트 창 안에서 정상적으로 열리는 것까지
  확인했습니다. Claude는 Cloudflare의 "사람 확인" 체크가 나올 수 있으며, 창 안에서 직접 누르면 됩니다.
- 서비스마다 로그인 판정에 쓰는 쿠키 이름(`shared/providers.json`)과 입력창 위치가 바뀌면 그 파일만 고치면 됩니다. 입력창을
  찾지 못하면 내용을 클립보드에 복사하고 알려 줍니다.
- Google은 임베디드 브라우저에서의 로그인을 거부할 수 있습니다("안전하지 않은 브라우저"). Trio는 정상적인 크롬 사용자 에이전트를
  쓰지만, 이런 보안 검사를 우회하지는 않습니다. 거부되면 "일반 탭에서 로그인"을 시도해 보세요(같은 프로필이라 로그인되면 바로
  풀립니다).
- 안드로이드: 사생활 보호 탭, 웹 페이지의 카메라·마이크·위치 권한은 아직 지원하지 않습니다(요청은 거절됩니다). 페이지가 직접 만든
  파일(blob:, data:)은 아직 내려받지 못하고 안내만 보여 줍니다. 앱이 백그라운드에서 정리되었다가 돌아오면 탭 주소는 복원되지만 페이지
  안의 상태, 뒤로 가기 기록, 에이전트 창은 복원되지 않습니다.
- Windows·macOS 패키지는 설정만 되어 있고 이 환경에서 만들어 보지는 않았습니다.
