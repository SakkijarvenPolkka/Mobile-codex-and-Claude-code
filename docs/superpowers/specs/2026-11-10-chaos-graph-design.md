# 카오스 그래프 (Chaos Graph) 설계

- 날짜: 2026-11-10
- 상태: 사용자 검토 대기
- 브랜치: `claude/eloquent-cerf-t54ml0`
- 테스트 기준값: [`2026-11-10-chaos-graph-reference-values.json`](2026-11-10-chaos-graph-reference-values.json)

## 1. 목적

카오스 이론의 대표적인 계를 고르면 그 그래프를 **자동으로 그려 주고**, 사용자가 확대·이동·회전하고
매개변수를 바꿔 가며 **볼 수 있는** 프로그램을 만든다. 같은 프로그램이 PC와 안드로이드에서 돌아가야
하고, 안드로이드 권장 기기는 갤럭시 Z 폴드8 울트라다.

### 1.1 요청과 가정

| 구분 | 내용 |
|---|---|
| 요청 | 대표 함수들의 카오스 그래프를 자동으로 그리고 볼 수 있을 것 |
| 요청 | PC와 안드로이드 모두에서 실행될 것 |
| 요청 | 권장 사양은 갤럭시 폴드 8 울트라 |
| 가정 | 용도는 선호 없음이라는 답에 따라 범용 탐색기로 만든다 (짧은 설명과 매개변수 조절 포함) |
| 가정 | 화면 글자는 한국어가 기본이고 영어로 바꿀 수 있다 |
| 가정 | 새 폴더 `chaos/`에 만들고 기존 Audacity 파일은 건드리지 않는다 |

### 1.2 성공 기준

1. PC에서 `chaos-graph.html` 파일 하나를 최신 Chrome, Edge, Firefox로 열면 네트워크 없이 로지스틱
   사상의 분기도가 그려진다.
2. 안드로이드 10 이상에서 APK를 설치하면 같은 화면이 뜨고, 폴드8 울트라의 커버 화면, 펼친 화면,
   반쯤 접은 상태에 맞게 배치가 바뀐다.
3. 36개 계 모두 고르는 즉시 대표 매개변수로 기본 그래프가 그려진다.
4. 수식과 적분기가 기준값 파일의 수치를 허용 오차 안에서 재현한다.
5. 터치와 마우스·키보드로 확대, 이동, 회전, 매개변수 조절이 된다.
6. 단위 테스트와 브라우저 테스트가 통과하고, 문서에 적힌 명령으로 빌드가 재현된다.

실제 폴드 기기에서의 동작, 120Hz 유지, 발열은 이 개발 환경에서 확인할 수 없다. 설치 후 사용자가
확인하고 결과에 따라 조정한다.

## 2. 범위

### 2.1 포함

- 36개 계 (7장) 와 9가지 그래프 종류 (8장)
- 자동 그리기: 고르면 바로 시작, 시야 자동 맞춤, 점진적으로 선명해짐, 3차원 자동 회전, 둘러보기
- 조작: 확대, 이동, 회전, 매개변수 슬라이더, 재생과 일시정지, 초기화, PNG 저장
- 계마다 수식과 두세 문장 설명 (한국어, 영어)
- 화면 크기와 접힘 상태에 따른 배치 전환, 어두운 테마와 밝은 테마
- PC용 단일 HTML 파일과 안드로이드 APK

### 2.2 범위 밖

- 사용자가 직접 수식을 입력하는 기능
- 삼체 문제, 자석 진자, 에농–헤일스, 매키–글래스, 뉴턴 프랙털, 랴푸노프 프랙털 (전용 코드가 필요해
  1차에서 제외. 기준값은 일부 계산되어 있다)
- 64비트 실수 한계를 넘는 프랙털 초고배율 확대
- 동영상 내보내기, 계정, 클라우드 저장
- 웹 주소로 배포하는 설치형 PWA
- iOS 전용 대응 (WebGL2가 되는 브라우저에서는 열리지만 검증 대상이 아니다)
- 2차원 사상과 흐름의 분기도 (1차원 사상만 분기도를 제공한다)

## 3. 대상 환경

### 3.1 권장 기기

2026-11-10 웹 조사 결과다. 사양은 삼성 공식 자료에서 왔고, 논리 화면 크기는 리뷰 스크린샷에서
역산한 값이라 공식 수치가 아니다. 교차 검증은 실행되지 못했다.

| 항목 | 갤럭시 Z 폴드8 울트라 (SM-F976) |
|---|---|
| 펼친 화면 | 8.0형, 2256×2504 픽셀, 20:18, 1~120Hz |
| 커버 화면 | 6.5형, 1080×2520 픽셀, 21:9, 1~120Hz |
| 논리 크기 (추정) | 펼침 약 752×835dp, 커버 약 360×840dp, 화소 배율 3 |

| 기타 | S펜 미지원, 플렉스 모드 지원 |

기기 상수를 코드에 넣지 않는다. 배치는 창 크기와 접힘 상태로만 정한다 (11.1절).

### 3.2 지원 환경

| 환경 | 조건 |
|---|---|
| PC 브라우저 | WebGL2를 지원하는 Chrome, Edge, Firefox 최신판. Safari는 열리지만 검증 대상이 아니다 |
| 안드로이드 APK | 안드로이드 10 (API 29) 이상, 시스템 WebView |
| 안드로이드 브라우저 | HTML 파일이 열릴 것으로 보이나 확인하지 못했다. 검증 대상은 APK다 |

WebGL2가 없으면 안내문을 보여 주고 멈춘다. 대체 렌더러는 만들지 않는다.

## 4. 접근 방식

**웹 기술 한 벌**로 만든다. TypeScript와 WebGL2로 프로그램을 작성하고, 빌드 결과는 스스로 완결된
HTML 파일 하나다. PC에서는 그 파일을 브라우저로 열고, 안드로이드에서는 같은 파일을 담은 얇은 WebView
앱(APK)으로 설치한다.

| 후보 | 채택 여부와 이유 |
|---|---|
| 웹 기술 한 벌 | 채택. 코드가 한 벌이고, GPU로 밀도 렌더링을 하며, 개발 환경의 Chromium으로 폴드와 PC 크기를 실제 렌더링해 검증할 수 있다 |
| Kotlin Compose Multiplatform | 미채택. Windows 설치 파일을 만들려면 Windows 빌드 머신이 필요하고 밀도 렌더링을 CPU로 해야 한다 |
| Flutter | 미채택. 툴체인을 새로 들여야 하고 Windows 빌드에 Windows가 필요하다 |

채택안의 비용은 APK 안에서 접힘 감지 API를 쓸 수 없다는 점이다. 네이티브 쪽에서 접힘 상태를 읽어
페이지로 넘기는 다리를 둔다 (13장).

## 5. 저장소 구성

```
chaos/
  README.md                사용법 (한국어, 짧은 영어 요약)
  web/                     프로그램 본체
    index.html  package.json  tsconfig.json  vite.config.ts
    src/
      core/                순수 계산. DOM과 WebGL에 의존하지 않는다
      compute/             워커와 작업 분배
      render/              WebGL2 렌더러, 2차원 겹침 캔버스, 보기 컨트롤러
      ui/                  화면 구성 요소, 배치 규칙
      i18n/                한국어, 영어 문자열
      host/                안드로이드 껍데기와의 다리
    tests/unit/            Vitest
    tests/e2e/             Playwright
  android/                 Gradle 모듈 `:chaos` (WebView 껍데기)
docs/superpowers/specs/    이 문서와 기준값 파일
docs/superpowers/plans/    구현 계획
```

기존 파일은 두 곳만 고친다.

- `settings.gradle.kts`: `include(":chaos")` 와 `project(":chaos").projectDir = file("chaos/android")`
- `gradle/libs.versions.toml`: `androidx.webkit`, `androidx.window` 항목 추가

웹 쪽 실행 의존성은 Preact와 `@preact/signals` 둘뿐이다. 수식 표시, 3차원 수학, 색상표는 직접
작성한다. 개발 의존성은 TypeScript, Vite, `vite-plugin-singlefile`, Vitest, Playwright다. 버전은 구현
시점의 최신 안정판을 쓰고 `package-lock.json`으로 고정한다.

## 6. 구조 개요

```
                 ┌──────────────── 화면 (ui) ────────────────┐
 입력(터치·마우스·키) ─► 상태 저장소(signals) ◄─► URL 해시 · localStorage
                          │
                          ▼
                 보기 컨트롤러 (render/views)  ── 계 하나에 세션 하나
                  │                  │
     정적 밀도 보기                실시간 보기
  (분기도·끌개·단면·프랙털)      (궤적·시계열·나비 효과·진자·거미줄)
          │                          │
   워커 풀 (compute)            메인 스레드 시뮬레이션 (core/sim)
   격자에 누적 → 조각 전송        RK4 고정 간격, 프레임당 시간 예산
          │                          │
          ▼                          ▼
   FieldLayer (R32F 텍스처)     LineDensity (선분을 실수 버퍼에 가산)
          └──────── 톤 매핑 + 색상표 ───────┘
                          │
                 WebGL 캔버스 + 2차원 겹침 캔버스(축, 눈금, 곡선, 진자)
```

핵심 규칙은 세 가지다.

1. **계산과 화면을 분리한다.** `core/`는 Node에서 그대로 돌아가고 단위 테스트의 대상이다.
2. **무거운 정적 계산은 워커에서, 가벼운 실시간 적분은 메인 스레드에서 한다.** 로렌즈 한 프레임에
   필요한 RK4는 수십 단계라서 워커 왕복보다 직접 계산이 싸다.
3. **세션은 보기와 독립이다.** 궤적에서 시계열로 바꿔도 시뮬레이션이 이어진다.

## 7. 계 카탈로그

36개다. 대표 9개를 먼저 보여 주고 나머지는 묶음별로 나열한다.
**대표:** 로지스틱 사상, 로렌즈 끌개, 뢰슬러 끌개, 에농 사상, 이중 진자, 망델브로 집합, 쥘리아 집합,
더핑 진동자, 추아 회로.

매개변수 범위 안에서 궤적이 발산할 수 있다. 그때는 15장의 발산 처리를 따른다.
`abs`는 절댓값이고 `'`는 다음 값이다.

### 7.1 1차원 사상 (5)

보기: 분기도(기본), 거미줄 그림, 시계열.

| id | 이름 | 식 | 기본값 (슬라이더 범위) | 분기도 가로축 | 세로축 | x₀ |
|---|---|---|---|---|---|---|
| `logistic` | 로지스틱 사상 | `x' = r·x·(1 − x)` | r = 3.9 (0~4) | r: 2.5~4 | 0~1 | 0.2 |
| `tent` | 텐트 사상 | `x' = μ·min(x, 1 − x)` | μ = 1.9 (0.5~1.9999) | μ: 1~1.9999 | 0~1 | 0.3 |
| `sine` | 사인 사상 | `x' = r·sin(πx)` | r = 0.95 (0~1) | r: 0.6~1 | 0~1 | 0.3 |
| `gauss` | 가우스 사상 | `x' = exp(−α·x²) + β` | α = 6.2 (1~10), β = −0.5 (−1~1) | β: −1~1 | −1~1.5 | 0.1 |
| `ricker` | 리커 사상 | `x' = x·exp(r·(1 − x))` | r = 3 (0~4) | r: 1.5~4 | 0~5.5 | 0.5 |

텐트 사상의 μ는 2 미만으로 막는다. μ = 2에서는 이진 부동소수점 궤도가 50여 번 만에 0으로 무너진다.

### 7.2 2차원 사상 (8)

보기: 끌개(기본), 시계열.

| id | 이름 | 식 | 기본값 (범위) | 초기값 | 기본 시야 |
|---|---|---|---|---|---|
| `henon` | 에농 사상 | `x' = 1 − a·x² + y`, `y' = b·x` | a = 1.4 (0.2~1.42), b = 0.3 (0~0.3) | (0, 0) | x: ±1.5, y: ±0.45 |
| `lozi` | 로지 사상 | `x' = 1 − a·abs(x) + y`, `y' = b·x` | a = 1.7 (1~1.8), b = 0.5 (0~0.6) | (0, 0) | x: ±1.6, y: ±0.8 |
| `ikeda` | 이케다 사상 | `t = 0.4 − 6/(1 + x² + y²)`, `x' = 1 + u·(x·cos t − y·sin t)`, `y' = u·(x·sin t + y·cos t)` | u = 0.9 (0.5~0.95) | (0.1, 0.1) | x: −0.6~2, y: −2.5~1.2 |
| `standard` | 표준 사상 (치리코프) | `p' = p + K·sin θ`, `θ' = θ + p'` (둘 다 mod 2π) | K = 0.97 (0~5) | 묶음 300개 | 0~2π 정사각형 |
| `tinkerbell` | 팅커벨 사상 | `x' = x² − y² + a·x + b·y`, `y' = 2xy + c·x + d·y` | a = 0.9 (0.7~0.92), b = −0.6013 (−0.65~−0.55), c = 2 (1.9~2.1), d = 0.5 (0.4~0.55) | (−0.72, −0.64) | x: −1.4~0.6, y: −1.7~0.7 |
| `clifford` | 클리퍼드 끌개 | `x' = sin(a·y) + c·cos(a·x)`, `y' = sin(b·x) + d·cos(b·y)` | a = −1.4, b = 1.6, c = 1, d = 0.7 (모두 −3~3) | (0.1, 0.1) | x: ±(1 + abs(c)), y: ±(1 + abs(d)) |
| `dejong` | 더용 끌개 | `x' = sin(a·y) − cos(b·x)`, `y' = sin(c·x) − cos(d·y)` | a = 1.4, b = −2.3, c = 2.4, d = −2.1 (모두 −3~3) | (0.1, 0.1) | ±2 정사각형 |
| `gingerbread` | 진저브레드맨 사상 | `x' = 1 − y + abs(x)`, `y' = x` | 매개변수 없음 | 묶음 200개 | −4.5~9 정사각형 |

넓이를 보존하는 `standard`와 `gingerbread`는 끌개가 없다. 초기값 묶음을 시야 안에 고르게 뿌려 각각을
반복한다.

### 8.1 자동 그리기

- 계를 고르면 기본 보기가 대표 매개변수와 맞춤 시야로 곧바로 그려지기 시작한다.
- 정적 밀도 보기는 거친 그림이 먼저 나오고 누적될수록 선명해진다. 정해진 점 수에 이르면 멈춘다.
- 흐름은 처음 약 4초 동안 12배에서 1배로 줄어드는 속도로 그려 전체 모양이 빨리 보이게 한다.
- 3차원 보기는 초당 12도로 자동 회전한다. 화면을 만지면 멈추고 버튼으로 다시 켠다.
- **둘러보기**는 대표 계를 12초마다 넘긴다. 입력이 들어오면 멈춘다.
- 움직임 줄이기 설정이 켜져 있으면 자동 회전과 둘러보기 자동 시작을 끈다.

### 8.2 보기별 세부

**분기도.** 열 하나가 매개변수 값 하나다. 열마다 600번을 버린 뒤 64점씩 누적하고, 열마다 최대
5만 점에서 멈춘다. 열의 상태를 유지하므로 다음 회차에 과도 구간을 다시 버리지 않는다. 랴푸노프
지수는 같은 반복에서 `ln abs(f'(x))`의 평균으로 구한다. 현재 매개변수 값에 세로 표시선이 있고 끌어서
옮길 수 있다. 이 값은 거미줄 그림, 시계열과 공유한다.

**끌개.** 소산계는 궤도 하나를 100번 버린 뒤 누적한다. 넓이 보존 사상은 초기값 묶음을 쓴다.
2억 점에서 멈춘다.

**푸앵카레 단면.** 워커마다 초기값을 조금씩 달리해 50주기를 버린 뒤 주기마다 한 점을 찍는다.
위상 슬라이더(0~2π)로 단면 시각을 옮긴다. 200만 점에서 멈춘다.

**위상 궤적.** 최근 선분을 고리 버퍼에 담아 둔다. 카메라가 움직이면 버퍼 전체를 다시 그리고,
카메라가 멈춰 있으면 새 선분만 덧그려 누적한다. 색 기준은 밀도 또는 속도다. 3차원에는 방향 표시
(x, y, z 축)와 XY, XZ, YZ 보기 버튼이 있다.

**나비 효과.** 둘째 궤적은 첫째에서 x로 10⁻⁸만큼 떨어져 출발한다. 거리 로그 그래프의 직선 구간
기울기에서 최대 랴푸노프 지수 추정값을 보여 준다. "다시 벌리기"로 둘째를 첫째 옆에 다시 놓는다.

**프랙털.** 8화소, 4화소, 2화소, 1화소 간격으로 차례로 채운다. 반복 한도는
`clamp(100 + 50·log₂(3.2/너비), 100, 4000)`에 세밀도 배율(0.5~4)을 곱한다. 화소 간격이
`max(abs(중심 좌표), 1)`의 10⁻¹⁵배 아래로 내려가면 확대를 막고 한계를 알린다.

**진자.** 멈춘 상태에서 추를 끌어 각도를 정한다. 쌍둥이 진자는 θ₁이 10⁻⁶ 라디안 다르다.

## 9. 계산

### 9.1 워커 작업

워커 수는 `clamp(논리 코어 수 − 1, 1, 4)`다. 작업은 시야와 격자 크기를 받아 **워커 안에서 격자에
누적**하고, 바뀐 영역을 `Float32Array`로 복사해 넘긴다.

| 작업 | 나누는 방법 | 넘기는 단위 |
|---|---|---|
| 분기도 | 열 구간을 워커 수만큼 나눔 | 자기 구간의 띠 |
| 2차원 궤도 | 워커 하나 | 격자 전체 |
| 푸앵카레 단면 | 워커마다 다른 초기값 | 격자 전체 |
| 탈출 시간 | 행 묶음을 워커에 번갈아 배정 | 채운 행 묶음 |

- 메시지는 `start`, `cancel`, `credit` (메인 → 워커) 과 `update`, `done`, `error` (워커 → 메인) 다.
- 워커는 8~16ms 단위로 계산하고 그 사이에 메시지를 처리하므로 취소가 곧바로 먹힌다.
- 메인이 `credit`을 줘야 다음 `update`를 보낸다. 전송 간격은 100ms에서 시작해 1초까지 늘린다.
- 메인은 한 프레임에 텍스처 올리기를 한 번만 한다.
- 시야가 바뀌면 작업을 취소하고 새 세대로 다시 시작한다. 제스처 중에는 100ms에 한 번만 다시 시작한다.
- 난수는 씨앗이 고정된 `mulberry32`를 쓴다. 같은 입력은 같은 격자를 만든다.

분기도의 열 값과 프랙털의 화소 좌표는 워커에서 64비트 실수로 계산한다. 화면 좌표로 바꾸는 일은
격자 색인 계산뿐이라 깊은 확대에서도 정밀도를 잃지 않는다.

### 9.2 실시간 시뮬레이션

- 적분기는 고정 간격 4차 룽게–쿠타다.
- 프레임마다 `실제 경과 시간 × 속도`만큼 시뮬레이션 시간을 쌓고 dt 단위로 소비한다.
- 한 프레임의 단계 수는 2만 또는 2ms 중 먼저 닿는 쪽에서 끊고, 밀린 시간은 버린다.
- 탭이 가려지면 멈춘다. 속도 슬라이더는 0.1~10배다.

### 9.3 발산 감지

상태의 절댓값이 10⁶을 넘거나 유한하지 않으면 발산으로 본다. 실시간 보기는 시뮬레이션을 멈추고
안내 띠를 띄운다. 워커 작업은 초기값 근처에서 다시 시작하고, 시도의 절반 이상이 발산하면 발산으로
보고한다.

## 10. 렌더링

캔버스 두 장을 겹친다. 아래는 WebGL2, 위는 2차원 캔버스(축, 눈금, 글자, 곡선, 진자)다.
화소 배율은 `min(devicePixelRatio, 2)`가 기본이고 품질 조절기가 1~3 사이에서 바꾼다.

### 10.1 FieldLayer

워커가 누적한 실수 격자를 그리는 층이다. 분기도, 끌개, 푸앵카레 단면, 프랙털이 함께 쓴다.

- 워커마다 R32F 텍스처 한 장을 갖고 자기 영역만 갱신한다. 셰이더가 최대 네 장을 더한다.
- R32F 텍스처를 읽기만 하므로 WebGL2 확장이 필요 없다.
- 층은 자기가 계산된 시야를 기억한다. 시야가 바뀌면 옛 그림을 새 시야에 맞춰 늘리거나 옮겨 그려서
  제스처가 화면 주사율로 따라온다.
- 앞뒤 두 벌을 두고, 새 세대의 첫 갱신이 모든 워커에서 오거나 150ms가 지나면 바꾼다.
- 밀도 모드의 밝기는 `ln(1 + n) / ln(1 + n_max)`다. 워커가 자기 격자의 최댓값을 함께 보낸다.
  영역을 나눠 맡는 작업은 그중 가장 큰 값을, 같은 화소에 겹쳐 쌓는 작업(푸앵카레 단면)은 합을
  `n_max`로 쓴다.
- 프랙털 모드는 ν를 순환 색상표에 대응시키고 집합 내부는 따로 칠한다. 값 0은 아직 계산하지 않은
  화소다.

### 10.2 LineDensity

적분한 궤적 선분을 그리는 층이다.

- 선분마다 정점 둘(위치 3, 스칼라 1)을 고리 버퍼에 넣고 `LINES`로 그린다. 각도가 접히는 선분은 뺀다.
- 실수 색 버퍼에 가산 혼합으로 그린다. R은 통과 횟수, G는 스칼라 합이다.
- `EXT_float_blend`가 있으면 RG32F, 없으면 RG16F를 쓰고 누적 한도를 낮춘다.
  `EXT_color_buffer_float`도 없으면 RGBA8에 낮은 알파로 그린다.
- 최댓값은 축소 연쇄(4배씩 줄이며 최댓값을 취함)로 1×1 텍스처까지 줄여 톤 매핑 셰이더가 직접 읽는다.
  CPU로 읽어 오지 않는다.
- 고리 버퍼 크기는 품질 단계에 따라 선분 10만~200만 개다.

### 10.3 색과 테마

색상표는 넷이다. 불씨(검정 → 빨강 → 노랑 → 흰색), 비리디스, 얼음, 흑백. 밝은 테마에서는 같은 표를
뒤집어 밀도가 높을수록 어둡게 한다. 테마는 시스템 설정을 따르고 손으로 바꿀 수 있다.

### 10.4 품질 자동 조절

`requestAnimationFrame` 간격의 중앙값으로 주사율을 잰다. 프레임 시간의 이동 평균이 예산의 1.25배를
30프레임 넘기면 한 단계 내리고, 0.6배 아래로 120프레임 머물면 한 단계 올린다. 단계는 다섯이고
화소 배율, 고리 버퍼 크기, 격자 화소 수 상한(기본 250만)을 함께 바꾼다. 설정에서 자동, 낮음, 높음을
고른다.

### 10.5 컨텍스트 손실

`webglcontextlost`에서 기본 동작을 막고, 복구되면 자원을 다시 만들고 현재 보기를 처음부터 그린다.

## 11. 화면과 조작

### 11.1 배치

`ui/layout`의 순수 함수가 창 크기(CSS 화소)와 접힘 상태로 배치를 정한다. 위에서부터 먼저 맞는 규칙을
쓴다.

| 조건 | 배치 | 해당하는 화면 |
|---|---|---|
| 반쯤 접힘, 접힘선 가로 | 위아래 분할. 접힘선 위가 그래프, 아래가 조작부 | 플렉스 모드 (탁자 자세) |
| 반쯤 접힘, 접힘선 세로 | 좌우 분할. 접힘선 왼쪽이 그래프 | 책 자세 |
| 높이 < 480, 너비 ≥ 600 | 그래프가 가득 차고 조작부는 오른쪽 서랍 | 커버 화면 가로 (840×360) |
| 너비 < 600 | 위 그래프, 아래 시트 (접힘 64dp, 펼침 50%) | 커버 화면 세로 (360×840), 일반 폰 |
| 너비 ≥ 840 이고 너비/높이 ≥ 1.25 | 왼쪽 그래프, 오른쪽 패널 (360~400dp). 너비 ≥ 1200이면 왼쪽에 계 목록 | PC, 가로로 넓은 창 |
| 그 밖 | 위 그래프 (60%), 아래 고정 패널 (40%, 두 단) | 펼친 화면 (752×835, 835×752) |

- 아래 고정 패널은 두 단 사이에 32dp 간격을 두어 접힘선 위에 슬라이더와 작은 글씨가 오지 않게 한다.
- 모든 배치에서 조작부를 접어 그래프만 볼 수 있다.
- 화면 방향을 고정하지 않는다. 접거나 펼쳐도 상태(매개변수, 시야, 시뮬레이션 시간)를 유지한다.
- 누를 수 있는 요소는 48dp 이상이다. 안전 영역은 `env(safe-area-inset-*)`로 비운다.

접힘 상태는 두 군데서 온다. APK에서는 네이티브 다리가 알려 주고, 브라우저에서는
`navigator.devicePosture`와 `window.viewport.segments`가 있을 때만 쓴다. 둘 다 없으면 펴진 것으로 본다.

### 11.2 화면 구성

- **앱 바:** 계 이름(누르면 계 선택), 재생·일시정지, 초기화, 시야 맞춤, 더 보기(PNG 저장, 둘러보기,
  언어, 테마, 품질, 색상표).
- **보기 탭:** 그 계에서 쓸 수 있는 그래프 종류.
- **매개변수:** 슬라이더와 숫자 입력, 미세 조절 버튼, 기본값 되돌리기, 프리셋.
- **보기 설정:** 보기마다 다른 항목 (랴푸노프 띠, 자동 회전, 색 기준, 세밀도 등).
- **설명:** 수식과 두세 문장 설명. 수식은 계 정의에 든 HTML 조각이고 사용자 입력을 넣지 않는다.
- **계 선택:** 대표, 1차원 사상, 2차원 사상, 3차원 끌개, 진동자와 진자, 프랙털로 묶은 목록.

### 11.3 조작

| 동작 | 터치 | 마우스·키보드 |
|---|---|---|
| 이동 (2차원) | 한 손가락 끌기 | 끌기, 방향키 |
| 확대 | 두 손가락 벌리기 | 휠, `+` `−` |
| 가로만 또는 세로만 확대 | 없음 | Shift + 휠, Alt + 휠 |
| 회전 (3차원) | 한 손가락 끌기 | 끌기 |
| 시야 맞춤 | 두 번 탭 | 두 번 클릭, `0` |
| 재생·일시정지 | 버튼 | 스페이스 |
| 이전·다음 계 | 버튼 | `[` `]` |

포인터 이벤트 하나로 터치와 마우스를 처리하고, 그래프 영역에는 `touch-action: none`을 준다.

### 11.4 언어와 접근성

브라우저 언어가 한국어면 한국어, 아니면 영어로 시작하고 설정에서 바꾼다. 두 언어의 문자열 키가
같은지 테스트로 확인한다. 슬라이더는 기본 `<input type="range">`를 써서 키보드와 화면 낭독기로 다룰 수
있다. 색상표에 색각 이상에 안전한 비리디스를 포함하고 글자 대비는 4.5:1 이상으로 한다.

## 12. 상태 저장과 링크

- URL 해시에 계, 보기, 매개변수, 시야를 담는다. 예: `#s=lorenz&v=trajectory&p=sigma:10,rho:28`.
  모르는 키는 무시하고 범위를 벗어난 값은 범위 안으로 당긴다.
- `localStorage`의 `chaos-graph:v1`에 설정과 마지막 계, 매개변수를 저장한다. 저장소를 쓸 수 없으면
  조용히 넘어간다.
- 테스트용으로 `window.__chaos`를 둔다 (준비 완료 Promise, 현재 상태, 누적 통계, 배치 이름).

## 13. 안드로이드 껍데기

Gradle 모듈 `:chaos`, 패키지 `io.github.sakkijarvenpolkka.chaos`, 앱 이름 "카오스 그래프"다.
`minSdk` 29, `compileSdk`와 `targetSdk` 36이고, 저장소의 다른 앱처럼 릴리스 빌드를 디버그 키로
서명한다. Compose는 쓰지 않는다. 액티비티 하나에 WebView 하나다.

- **자산:** `chaos/web/dist/index.html`을 빌드 때 자산으로 복사한다. 파일이 없으면 먼저 웹을 빌드하라는
  메시지와 함께 실패한다. `WebViewAssetLoader`로 `https://appassets.androidplatform.net/`에서 제공한다.
- **보안:** 파일 접근과 콘텐츠 접근을 끄고, 앱 밖 주소로 가는 탐색을 막는다. 자바스크립트 인터페이스는
  번들된 페이지에만 노출된다.
- **접힘 다리:** Jetpack WindowManager의 `FoldingFeature`(상태, 방향, 경계)를 CSS 화소로 바꿔 페이지에
  넘긴다.
- **PNG 저장:** 페이지가 base64로 넘긴 그림을 MediaStore의 `Pictures/ChaosGraph`에 저장한다.
  파일 이름을 정리하고 크기를 50MB로 제한한다.
- **뒤로 가기:** 페이지가 먼저 처리하고(시트, 계 선택 닫기) 처리할 것이 없으면 앱을 닫는다.
- **기타:** 화면 끝까지 그리기, 접거나 돌릴 때 액티비티를 다시 만들지 않기, 렌더러가 죽으면 WebView를
  다시 만들기.

## 16. 테스트와 검증

### 16.1 단위 테스트 (Vitest, Node)

- **기준값:** 기준값 파일의 정확값, 골든값, 통계값, 불변량을 TypeScript 구현이 허용 오차 안에서
  재현한다. 예: 로지스틱 주기배가 r₁ = 3, r₂ = 1 + √6, r = 4에서 랴푸노프 지수 ln 2, 에농 고정점과
  두 지수의 합 ln b, 로렌즈 최대 지수 0.906 근처와 지수 합 −(σ + 1 + β), 표준 사상의 넓이 보존.
- **적분기:** 조화 진동자에서 dt를 반으로 줄이면 오차가 약 16분의 1이 된다. 흐름마다 초기값에서 1단계,
  100단계 뒤의 값을 독립된 파이썬 구현과 10⁻⁹ 안에서 맞춘다.
- **이중 진자:** dt = 0.002로 적분한 에너지 변화의 절댓값이 기준값 파일의 한도 안에 든다 (기본
  초기값의 에너지가 0이라 상대값을 쓰지 않는다). 작은 각도의 진동수가 정규 모드와 맞는다.
- **카탈로그 무결성:** 모든 계에서 기본값이 범위 안에 있고, 기본 초기값에서 10만 단계 동안 유한하며,
  표본 점의 99% 이상이 기본 시야 안에 든다.
- **작업:** 같은 입력에 같은 격자가 나온다. 분기도 격자에서 r = 2.8 열은 한 무리, r = 3.2 열은 두 무리,
  r = 3.83 열은 세 무리다. 망델브로에서 c = 0과 c = −1은 내부, c = 1은 외부다.
- **순수 로직:** 시야 변환(한 점을 기준으로 확대하면 그 점이 제자리), 눈금, URL 변환 왕복과 범위 보정,
  배치 규칙(11.1절 표의 모든 행), 품질 조절기, 제스처 상태 기계, 두 언어의 키 일치.

### 16.2 브라우저 테스트 (Playwright, Chromium)

개발 환경의 Chromium은 소프트웨어 GPU라서 속도는 실제 기기와 다르다. 동작과 그림의 내용을 본다.

- **모든 계:** 36개 계의 기본 보기가 10초 안에 빈 화면이 아닌 그림을 내고, 콘솔 오류가 없다.
- **그림 내용:** 분기도 캔버스의 열을 읽어 무리 수가 16.1절과 같다. 망델브로 그림이 실수축에 대칭이고
  c = 0 화소가 내부 색이다.
- **배치:** 360×840, 752×835, 835×752, 840×360, 1280×800, 1920×1080에서 가로 넘침이 없고, 그래프가
  창 넓이의 40% 이상이며, 누를 수 있는 요소가 44 CSS 화소 이상이고, 아래 고정 패널의 조작 요소가
  가운데 간격에 걸치지 않는다. 접힘 상태는 호스트 다리의 이벤트를 흉내 내어 넣는다.
- **조작:** 휠과 끌기로 눈금이 바뀐다. 터치 두 점으로 확대된다. 슬라이더를 움직이면 URL 해시와 그림이
  바뀐다. 일시정지하면 그림이 변하지 않는다.
- **단일 파일:** `file://`로 열어도 동작하고 네트워크 요청이 0건이다.
- **메인 스레드:** 분기도와 프랙털을 그리는 동안 100ms를 넘는 긴 작업이 없다.

### 16.3 안드로이드

Robolectric 단위 테스트로 액티비티 시작, 자산 경로 대응, 접힘 정보 변환, 파일 이름 정리를 확인한다.
`assembleRelease`가 성공하고 APK 안에 `index.html`이 있는지 확인한다. 개발 환경에는 에뮬레이터를 돌릴
가상화 장치가 없어 기기 실행은 사용자가 한다.
