# 파일 탐색기 (`:explorer`) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 이 저장소에 Windows 11 파일 탐색기 모습의 독립 Android 파일 관리자 앱 `:explorer`를 만들고 설치 가능한 APK를 낸다.

**Architecture:** 순수 Kotlin `fs/` 계층(FsBackend 뒤의 NIO, 쓰기 규칙, 작업, 휴지통, 검색, ZIP)을 JVM 테스트로 굳히고, 그 위에 `ops/`(포그라운드 서비스에서 도는 직렬 작업 실행기와 저널), `state/`(순수 리듀서와 로더), `platform/`(권한, 볼륨, MIME, 열기), `ui/fluent/`(Compose Foundation 위 자체 Fluent 컴포넌트), `ui/`·`preview/`를 쌓는다.

**Tech Stack:** Kotlin 2.3.21, AGP 8.13.2, Gradle 8.14.3, Compose BOM 2025.12.01(ui, ui-graphics, foundation), lifecycle 2.9.4, activity-compose 1.11.0, coroutines 1.10.2, kotlinx.serialization 1.9.0, JUnit 4.13.2, Robolectric 4.16.

**Spec:** `docs/superpowers/specs/2026-10-23-explorer-design.md` (이하 "사양 §N"). 실행자는 계획과 사양을 함께 읽는다. 계획에 없는 세부(문구 외의 레이아웃 수치, 아이콘 모양)는 사양을 따른다.

## Review Focus

사양이 암시하지만 쉽게 빠지는 다섯 가지. 각 줄의 테스트는 담당 작업에 들어 있다.

1. **항목이 아주 많은 폴더**(예: `DCIM/.thumbnails` 2만 개): 목록이 메인 스레드를 막지 않고 정렬이 빠르다 → Task 2 `listsTwentyThousandEntriesQuickly`, Task 7 `loaderRunsOffMainAndKeepsRowsOnRefresh`.
2. **복사 중 원본 크기가 바뀜**(자라는 로그 파일): 읽은 만큼 복사하고 항목은 성공(쓴 크기는 "읽은 바이트"와 비교, 세기 단계 크기와 비교하지 않음) → Task 12 `copiesGrowingSourceAsRead`.
3. **목록과 실제가 어긋남**(탭하거나 작업하려는 파일이 이미 사라짐): NotFound 메시지 후 그 폴더를 새로 고침, 작업은 그 항목만 실패 → Task 12 `missingSourceIsPerItemFailure`, Task 9 `openingVanishedFileShowsNotFoundAndRefreshes`.
4. **같은 폴더를 연 탭이 둘**: 한 탭에서 끝난 작업이 그 폴더를 보는 모든 탭을 새로 고침 → Task 16 `finishedOpRefreshesEveryTabShowingAffectedFolder`.
5. **0바이트 파일과 빈 폴더**: 복사·이동·휴지통·ZIP 왕복에서 그대로 유지 → Task 12 `copiesEmptyFileAndEmptyDir`, Task 13 `binRoundTripKeepsEmptyDir`, Task 25 `zipRoundTripKeepsEmptyFileAndDir`.
