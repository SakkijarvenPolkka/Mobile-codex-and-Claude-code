# 파일 탐색기 (Files) — Windows 11 탐색기 스타일 파일 관리자

휴대폰의 내부 저장소·SD 카드·USB 드라이브를 Windows 11 파일 탐색기처럼 찾아보고, 복사·이동·삭제·이름 바꾸기·압축을
하고, 이미지·텍스트·오디오·동영상·PDF를 앱 안에서 보는 Android 파일 관리자입니다. Kotlin과 Jetpack Compose
Foundation 위에 Fluent 스타일 컴포넌트를 직접 만들어 얹었습니다(Material 3를 쓰지 않습니다).

> **비공식 앱입니다.** Windows 탐색기의 모습과 동작을 참고했을 뿐, Microsoft와 관련이 없고 그들의 승인을 받지
> 않았습니다. Windows는 Microsoft의 상표입니다. Microsoft의 이름·로고·아이콘 파일은 쓰지 않았고, 아이콘은
> 모두 벡터로 직접 그렸습니다. 앱 이름은 한국어 "파일 탐색기", 영어 "Files"입니다.

English summary: a standalone Android file manager that looks and behaves like the Windows 11 File Explorer
(Fluent design, command bar, tabs, home, light/dark). Unofficial look-alike, not affiliated with Microsoft.
It needs the "All files access" permission, runs on Android 11+, and has no third-party libraries. MIT license.
Other apps can pick files from it (ACTION_GET_CONTENT), and it appears in the system file picker, where they can
open, save, create, rename and delete files (deletions go to its Recycle Bin). See [Install](#설치) and [Build](#빌드).

이 앱은 같은 저장소의 Audacity 포팅(`:app`, `:engine`, `:editor`, `native/`)과 코드·빌드 의존이 없는 별개의
앱입니다.

## 기능

### 탐색

- **보기 4가지**: 자세히(이름·수정한 날짜·유형·크기 열), 목록, 타일, 큰 아이콘(썸네일 격자). 폴더마다 기억합니다.
- **정렬**: 이름·수정한 날짜·유형·크기, 오름/내림차순, 폴더 먼저. 열 머리글을 탭해도 정렬됩니다. 이름은 한글 NFC
  정규화, 대소문자 무시, 숫자 부분은 수치로 비교합니다(`2.txt` < `10.txt`).
- **주소 표시줄**: 경로 조각(브레드크럼)을 탭하면 그 폴더로, 조각 옆 ▾는 하위 폴더 목록, 빈 곳을 탭하면 실제 경로를
  직접 입력. 뒤로/앞으로/위로 버튼.
- **탭**: 가로 스크롤 탭 줄, 새 탭, 닫기, 다른 탭 닫기, 복제. 탭과 위치는 앱을 다시 열어도 복원됩니다.
- **홈**: 빠른 액세스(즐겨찾기와 다운로드·DCIM·사진·문서·음악·동영상), 드라이브별 사용량 막대, 최근 항목 20개,
  휴지통 크기.
- **즐겨찾기**: 폴더 고정/해제와 순서 바꾸기.
- **탐색 창**: 홈, 즐겨찾기, 내 PC(볼륨 목록), 휴지통. 휴대폰은 서랍, 너비 840dp 이상에서는 왼쪽에 고정됩니다.
- **미리보기 창**: 너비 840dp 이상에서 ⋯ ▸ 미리보기 창이나 Alt+P로 켜면 오른쪽에 붙습니다(처음에는 꺼져 있고, 켠 것은
  앱을 다시 시작하면 기억하지 않습니다). 선택한 파일 하나나 탭한 파일을 보여 주고, 창의 "열기"는 전체 화면으로 엽니다.
- **그 밖에**: 숨김 항목·파일 확장자 표시 설정, 속성 대화상자(폴더는 하위 항목을 세며 갱신), 밝게/어둡게/시스템 테마와
  시스템 강조색, 하드웨어 키보드 단축키(Ctrl+C/X/V/A, Delete, Shift+Delete, F2, F5/Ctrl+R, Ctrl+L, Ctrl+T/W,
  Ctrl+Tab, Alt+←/→/↑, Backspace(뒤로), Enter, Alt+P).

### 파일 작업

- 새로 만들기(폴더, 텍스트 문서), 복사·잘라내기·붙여넣기, 이름 바꾸기(확장자를 바꾸면 확인, 대소문자만 바꾸는 이름
  변경 지원), 삭제, 공유, 다른 앱으로 열기, APK 설치.
- **충돌 처리**: 대상 덮어쓰기 / 건너뛰기 / 둘 다 유지, "이후 충돌에도 모두 적용". 같은 이름의 폴더는 병합합니다
  (대상에만 있는 파일은 그대로 남습니다). 같은 폴더에 붙여넣으면 `- 복사본`으로 복사합니다.
- **휴지통**: 볼륨마다 `.Recycle.Bin`. 복원, 영구 삭제, 비우기. 휴지통으로 옮길 수 없으면 조용히 지우지 않고 영구 삭제 여부를 묻습니다.
- **백그라운드 진행**: 진행률 대화상자, 상태 표시줄의 진행률 칩, 데이터 동기화 포그라운드 서비스와 알림(취소 가능).
  화면을 꺼도 계속되고, 충돌이 있으면 알림이 "확인이 필요합니다"로 바뀝니다.
- **중단에 안전한 쓰기**: 임시 파일(`.xpart`)에 쓴 뒤 이름을 바꿔 확정합니다. 취소, 공간 부족, SD 카드 제거,
  강제 종료에도 원본은 지워지지 않고 잘린 파일이 완전한 파일처럼 남지 않습니다. 작업 저널이 앱을 다시 열 때
  남은 임시 파일을 정리하고 "작업이 중단되었습니다: X/Y 완료 — 다시 시도"를 보여 줍니다.
- **다른 앱의 저장과 함께**: 다른 앱이 시스템 선택기로 덮어써 저장하는 중인 파일과 그 파일이 든 폴더는 저장이 끝날
  때까지 이름을 바꾸거나 옮기거나 지울 수 없습니다(이름 바꾸기는 "진행 중인 작업이 사용하는 항목입니다", 이동·삭제는
  그 항목만 실패로 남기고 나머지는 계속합니다). 다른 볼륨으로 옮기는 도중 다른 앱이 원본을 새로 저장하면 원본을 지우지
  않고 두 판을 모두 남깁니다(실패 목록에 표시).
- 복사한 파일은 미디어 스캔을 해서 갤러리에 나타납니다.

### 미리보기

- **이미지**: JPG·PNG·WebP·GIF·HEIC·BMP·AVIF. 핀치/두 번 탭 확대(확대하면 더 높은 해상도로 다시 디코딩),
  좌우로 넘겨 같은 폴더의 이전/다음 이미지, 애니메이션 GIF/WebP.
- **텍스트**: UTF-8, UTF-16(BOM), 한국어 CP949를 자동 감지하고 ⋯에서 직접 고를 수도 있습니다. 줄 번호, 고정폭 글꼴,
  최대 1 MiB. 바이너리 파일은 "이 파일은 텍스트 파일이 아닙니다" 안내와 함께 "연결 프로그램"(다른 앱으로 열기) 버튼을
  보여 줍니다.
- **오디오·동영상**: Fluent 재생 컨트롤, 오디오 포커스 처리, 이어폰이 빠지면 일시정지, 앱이 가려지면 일시정지하고
  돌아오면 그 위치에서 다시 준비.
- **PDF**: 세로 스크롤, 핀치 확대, 암호 PDF·손상된 파일 안내.
- **썸네일**: 큰 아이콘·타일 보기와 미리보기 창에서 이미지·동영상·오디오 썸네일(캐시, 스크롤하면 취소).
- 미리보기를 지원하지 않는 형식이나 실패한 경우에는 "다른 앱으로 열기"를 제안합니다.

### 검색

- 현재 폴더(하위 폴더 포함)에서 파일 이름 검색. 부분 문자열과 `*`/`?` 패턴, 한글 NFC·대소문자 무시.
- 찾는 대로 결과가 채워지고, 현재 순회 중인 폴더와 건너뛴 폴더 수를 보여 줍니다. 최대 10,000개.
- 결과에서 열기·복사·잘라내기·삭제·이름 바꾸기·압축이 되고, 뒤로 가면 원래 폴더로 돌아갑니다.

### ZIP

- 선택한 항목을 ZIP(UTF-8 이름)으로 압축, "모두 압축 풀기".
- **한국어 ZIP**: Windows(한국어)에서 만든 CP949 이름을 자동 감지해 풀고, 대화상자에서 자동 / UTF-8 / 한국어 CP949를
  고를 수 있습니다. macOS의 NFD 한글 이름도 NFC로 바로잡습니다.
- **안전한 풀기**: `..` 조각·절대 경로·드라이브 접두어(`C:`)·제어 문자가 든 이름이 하나라도 있으면 아무것도 풀지 않고
  거부합니다(역슬래시는 `/`로 바꿉니다. Android 14+의 `ZipPathValidator`가 거부해도 같은 메시지). 선언 크기를 넘거나
  CRC가 다른 항목은 중단하고, 임시 폴더에 푼 뒤 통째로 이름을 바꿔 확정합니다.
- 암호 ZIP은 지원하지 않습니다(암호로 보호된 ZIP이라는 안내만 합니다).

### 다른 앱과 시스템 선택기

- **다른 앱에 파일 골라 주기**: 다른 앱이 파일을 달라고 할 때(`ACTION_GET_CONTENT`, 예: 크롬의 파일 올리기, 메신저의
  파일 첨부) "파일 탐색기"를 고르면 탐색기가 "파일 선택" 모드로 열립니다. 요청한 형식에 맞는 파일만 고를 수 있고, 맞지
  않는 파일은 흐리게 보이며 눌러도 반응하지 않습니다. 파일 하나를 원하면 누른 파일을 바로 돌려주고, 여러 개를 원하면
  눌러서 고른 뒤 "열기 (N)"으로 한 번에 최대 500개까지 돌려줍니다.
- **선택 모드**: 새로 만들기·붙여넣기·이름 바꾸기·삭제·압축처럼 파일을 바꾸는 명령과 휴지통, 미리보기 창, 내장 뷰어가
  없습니다. 탭 하나로만 열리고 앱의 탭과 세션은 읽지도 저장하지도 않습니다. 그 앱은 돌려받은 파일의 이름과 크기를 알 수
  있고, 파일을 읽을 수만 있습니다. 고른 파일은 최근 항목에 들어가고, 다음 선택은 그 폴더에서 시작합니다(없으면 홈).
  여러 개를 고를 때 링크를 누르면, 그 대상이 지금 목록(폴더나 검색 결과)에 있으면 고른 파일에 더하고, 다른 폴더에
  있으면 그 폴더로 가서 고릅니다. 앱에서 하던 파일 작업이 끝나면, 그 작업이 바꾼 폴더(또는 그 아래를 찾은 검색 결과)를
  보고 있을 때 다시 읽습니다(작업의 진행·결과·안내는 선택 화면에 보이지 않습니다). 돌려줄 수 없는 파일이면 "이 파일은
  열 수 없습니다"를 보이고 아무것도 돌려주지 않습니다. 탐색기가 모든 파일 관리 권한을 받기 전에 시작된 경우(예: 다른
  앱에서 처음 열어 권한을 준 경우), 탐색기를 다시 시작하기 전까지 선택 모드에서는 USB 드라이브가 "이 폴더에 접근할 수
  없습니다"로만 보이며 다시 시작을 제안하지 않습니다.
- **시스템 파일 선택기**: 모든 파일 관리 권한이 있으면 Android 파일 선택기(다른 앱의 "열기", "다른 이름으로 저장", "폴더
  선택")의 옆면에 "파일 탐색기"가 나옵니다. 그 안에는 즐겨찾기 폴더, 그다음 드라이브가 있고, 최근 항목(탐색기에서 최근 연
  파일. 선택기의 "최근" 화면에 다른 앱의 최근 파일과 함께 보이며, 선택기는 45일 안에 수정한 파일만 보여 줍니다), 모든
  드라이브의 이름 검색(최대 200개·5초. 선택기의 형식·크기·날짜 칩을 따르고, "최근" 화면에서 검색하면 미디어 저장소가
  색인하는 드라이브(내부 저장소, SD 카드)의 사진·동영상·음악·문서는 선택기가 미디어 항목으로 따로 보여 주므로 빼서
  겹치지 않게 합니다), 사진·동영상 썸네일(최대 2048픽셀)을 지원합니다. 권한을 회수하면 탐색기는 아무 문서도 내주지
  않고, 선택기는 다음에 탐색기를 부를 때 "파일 탐색기"를 뺍니다. 파일 시스템 UUID가 없는 USB 드라이브(시스템이
  `public:8,1`처럼 부르는 드라이브)는 시스템 선택기에 나오지 않습니다(앱 안에서는 열립니다). 드라이브를 꺼내거나,
  앱에서 파일 작업·이름 바꾸기·새로 만들기를 하거나 즐겨찾기 폴더를 바꾸면 열려 있는 선택기의 목록도 다시 읽힙니다.
- **선택기에서 바꾸기**: 다른 앱이 선택기를 통해 파일을 열고, 덮어쓰거나 다른 이름으로 저장하고, 파일·폴더를 만들고, 이름을
  바꾸고, 지울 수 있습니다. 이름은 앱 안과 같은 규칙으로 검사합니다. 새로 만들 때 이름이 겹치면 `이름 (2).확장자`로
  만들고, 확장자 없는 파일 이름에는 형식에 맞는 확장자를 붙입니다. 지운 항목은 탐색기의 휴지통으로 갑니다. 휴지통으로
  옮기지 못하면(예: 저장 공간이 가득 차 휴지통 기록을 쓸 수 없을 때, 휴지통 폴더를 만들거나 항목을 옮길 수 없을 때)
  물어볼 화면이 없어 내부 저장소에서도 바로 영구 삭제합니다. 시스템 "파일" 앱(이나 다른 앱)이 "파일 탐색기"를 통해 하는
  이동은 복사한 뒤 지우는 것이라, 옮긴 원본은 탐색기의 휴지통으로 가고 휴지통을 비울 때까지 자리를 차지합니다.
  탐색기에서 진행 중인 작업이 쓰는 항목(그 작업의 원본과 대상, 그 안의 항목, 그것을 담은 폴더)은 선택기에서도 이름을
  바꾸거나 지울 수 없습니다. 읽기 전용으로 연결된 드라이브는 바꾸지 않습니다.
- **안전한 덮어쓰기 저장**: 덮어쓰기(`"w"`/`"wt"`)는 같은 폴더의 임시 파일(`.xpart`)에 받아 두었다가, 쓴 앱이 닫으면
  디스크에 기록하고 한 번에 바꿔 넣습니다. 폴더까지 디스크에 기록하므로 그 직후 전원이 끊겨도 파일은 이전 내용이나 새
  내용 중 하나이고, 잘린 내용이 되지 않습니다. 쓴 앱이 `closeWithError`로 닫거나, 도중에 종료되거나, 파일을 닫지 않은 채
  버리거나(누수) `detachFd()`로 떼어 내면 원본이 그대로 남습니다(파일을 닫지 않는 앱은 저장을 잃습니다). 저장을 시작할
  때나 닫을 때 그 드라이브의 남은 공간이 1 MiB보다 적거나 알 수 없으면 저장을 받지 않거나 버리고 원본을 남깁니다(공간이
  모자라 잘린 쓰기와 끝난 쓰기는 닫는 방식으로 구별되지 않기 때문입니다). 그 밖에는 쓴 앱이 정상적으로 닫은 저장을 끝난
  것으로 보므로, 그 앱 자신의 쓰기가 실패했더라도 닫은 내용으로 바뀝니다. 저장을 닫은 직후의 다시 열기·조회·이름
  바꾸기·지우기는 탐색기가 새 내용을 제자리에 넣을 때까지 기다리므로 저장한 파일을 봅니다. 다른 앱이 저장 중인 파일이나
  그 파일이 든 폴더는 저장이 끝날 때까지 이름을 바꾸거나 옮기거나 지울 수 없습니다(앱에서는 "진행 중인 작업이 사용하는
  항목입니다"가 나옵니다). 탐색기가 그사이 종료되면 남은 임시 파일은 다음에 탐색기가 시작될 때 정리됩니다.
  덧붙이기·임의 위치 쓰기(`"wa"`, `"rw"`, `"rwt"`)는 원리상 파일에 직접 씁니다.
- **내주지 않는 것**: 폴더 선택(`ACTION_OPEN_DOCUMENT_TREE`)에서는 "파일 탐색기"의 맨 위 폴더, 모든 드라이브의
  루트(USB 드라이브 포함), 드라이브마다 맨 위에 있는 `Download`와 `Android` 폴더(대소문자 구분 없음)를 고를 수 없습니다.
  그 안의 폴더(`Android/media` 등)는 고를 수 있습니다. `Android/data`, 그리고 이 앱에 "출처를 알 수 없는 앱 설치"를
  허용했어도 `Android/obb`, 휴지통 폴더와 임시 파일은 선택기에 보이지 않고 문서 ID를 조작해도 닿을 수 없습니다. 볼륨
  밖도 마찬가지이며, 심볼릭 링크는 선택기에 내놓지 않습니다.

탐색하기, 백그라운드 음악 재생, 텍스트 편집, 실행 취소(Ctrl+Z), 이름 바꾸기·이동의 되돌리기 스낵바, 드래그 앤 드롭,

앱 안에서 다른 앱의 문서 공급자(클라우드 등) 탐색.

## 설치

Android 11(API 30) 이상이 필요합니다.

1. 릴리스 빌드로 만든 `explorer-release.apk`(빌드 참고)를 기기로 옮깁니다. 기기에서 "출처를 알 수 없는 앱 설치"를
   허용한 뒤 APK를 엽니다(sideload).
2. 처음 실행하면 **모든 파일 관리** 권한 화면이 나옵니다. 버튼을 눌러 설정에서 이 앱의 "모든 파일에 대한 액세스"를
   켜고 돌아오면 됩니다. 권한이 없으면 앱은 다른 화면을 보여 주지 않습니다.
3. Android 13 이상에서는 파일 작업의 진행 알림을 위해 알림 권한을 한 번 묻습니다(거부해도 작업은 동작합니다).

APK는 빌드한 컴퓨터의 디버그 키로 서명됩니다(배포용으로는 별도 키로 다시 서명하세요). 같은 컴퓨터에서 빌드한 1.0.x
위에는 지우지 않고 설치할 수 있습니다(설정 유지). 다른 컴퓨터에서 빌드한 1.0.x 위에는 서명이 달라 설치되지
않으므로(`INSTALL_FAILED_UPDATE_INCOMPATIBLE`) 먼저 지워야 하고, 그러면 설정도 지워집니다.

## 빌드

필요한 것: JDK 17 이상, Android SDK(platform 36, build-tools 36.0.0). 저장소 루트의 `local.properties`에 SDK 위치를
적습니다(커밋하지 않는 파일).

```properties
sdk.dir=/opt/android-sdk
```

이 앱은 Audacity 네이티브 엔진을 쓰지 않으므로 **모든 Gradle 명령에 `-Paudacity.buildNative=false`를 붙입니다**
(안 붙이면 NDK 빌드가 시작됩니다).

```sh
# 디버그 APK → explorer/build/outputs/apk/debug/explorer-debug.apk
./gradlew -Paudacity.buildNative=false :explorer:assembleDebug
# 릴리스 APK(R8 축소, 디버그 키 서명) → explorer/build/outputs/apk/release/explorer-release.apk
./gradlew -Paudacity.buildNative=false :explorer:assembleRelease
```

Maven Central이 HTTP 429를 돌려주면 잠시 뒤 같은 명령을 다시 실행하세요(Google 미러가 대체 저장소로 설정되어 있습니다).

### 테스트

```sh
# 단위·Robolectric Compose 테스트 전체 + 디버그 빌드 (각 변경의 통과 기준)
./gradlew -Paudacity.buildNative=false :explorer:testDebugUnitTest :explorer:assembleDebug
# 일부만
./gradlew -Paudacity.buildNative=false :explorer:testDebugUnitTest --tests '*ZipTest'
```

테스트 결과는 `explorer/build/test-results/testDebugUnitTest/`와 `explorer/build/reports/tests/`에 있습니다.
Gradle을 두 개 동시에 실행하지 마세요.

## 구조

소스는 `explorer/src/main/java/io/github/sakkijarvenpolkka/explorer/`에 있습니다. 위 층이 아래 층만 사용합니다
(`LayeringTest`가 확인합니다).

- `pick/` — 다른 앱의 파일 요청(`ACTION_GET_CONTENT`)을 받는 활동과 돌려줄 결과(요청 해석과 선택 규칙은 `state/`의
  `PickRequest`·`PickMode`)
- `ui/`, `ui/fluent/` — 화면(셸, 홈, 대화상자, 단축키)과 직접 만든 Fluent 컴포넌트·아이콘
- `preview/` — 이미지·텍스트·오디오/동영상·PDF 뷰어와 미리보기 창
- `state/` — ViewModel, 탭·위치·선택·명령 활성화 같은 UI 상태
- `provider/` — 시스템 파일 선택기의 문서 공급자: 문서 ID와 검사, 커서 행, 덮어쓰기 저장, 검색 인자, 변경 알림
- `ops/` — 작업 실행기, 포그라운드 서비스, 작업 저널, 알림
- `data/` — 설정과 세션 저장
- `platform/` — 볼륨 레지스트리, 다른 앱으로 열기, 썸네일, 미디어 스캔, 권한
- `fs/` — 파일 시스템 계층(Android API 없음): 쓰기 규칙, 파일 작업, 휴지통, 다른 앱이 진행 중인 저장, 순회기, 검색,
  ZIP, 이름 검사·정렬, 텍스트 감지
- `util/` — 표시 이름, 크기·날짜 형식, `UiText`

설계 문서: [`docs/superpowers/specs/2026-10-23-explorer-design.md`](../docs/superpowers/specs/2026-10-23-explorer-design.md),
[`docs/superpowers/specs/2026-11-07-explorer-pick-and-provider-design.md`](../docs/superpowers/specs/2026-11-07-explorer-pick-and-provider-design.md)
(다른 앱의 파일 선택과 시스템 선택기)

## 실기기 확인 목록

이 앱은 에뮬레이터가 없는 환경에서 만들었습니다. 단위·Robolectric 테스트(891개)는 통과하지만, 아래는 실제
기기에서 직접 확인해야 합니다. 확인한 항목에 체크하세요. 문제가 있으면 기기, Android 버전, 저장소 종류(내부/SD/USB)와
함께 알려 주세요.

### 저장소와 권한

- [ ] SD 카드에서 새로 만들기·복사·이동·이름 바꾸기·삭제(휴지통 포함)가 된다
- [ ] USB OTG 드라이브: 권한을 받기 전에 연결했을 때 "앱을 다시 시작하면 이 드라이브를 열 수 있습니다"와 다시 시작
      동작, 권한을 받은 뒤에는 바로 열린다
- [ ] `Android/data` 폴더에서(그리고 이 앱에 "출처를 알 수 없는 앱 설치"를 허용하기 전에는 `Android/obb`에서도)
      "Android에서 제한한 폴더" 배너가 보이고 새로 만들기·붙여넣기·이름 바꾸기가 막힌다
- [ ] "출처를 알 수 없는 앱 설치"를 허용한 뒤에는 `Android/obb`가 배너 없이 열리고 보통 폴더처럼 바꿀 수 있다
- [ ] SD에 있는 파일을 다른 앱으로 열 수 있다(FileProvider, `/storage/XXXX-XXXX/...`)
- [ ] APK를 탭하면 "출처를 알 수 없는 앱" 안내를 거쳐 설치 화면이 열린다

### 파일 작업

- [ ] 화면을 끈 채 10분 이상 걸리는 큰 복사가 끝까지 진행된다(포그라운드 서비스, 알림, WAKE_LOCK)
- [ ] 복사 중 SD 카드를 뽑으면 작업이 "N/M 완료"로 멈추고, 임시 파일이 남지 않으며, 앱이 종료되지 않는다
- [ ] 백그라운드에서 SD 카드를 꺼내면(`ACTION_MEDIA_EJECT`, 앱이 캐시된 상태) vold가 앱을 종료하기 전에 그 볼륨의
      열린 파일(미리보기·썸네일·PDF·미디어)이 닫힌다
- [ ] 복사 중 설정에서 전체 파일 접근 권한을 회수하면 앱이 종료되고, 다시 열었을 때 저널이 남은 임시 파일을 정리한다
- [ ] 이름 바꾸기 대화상자 위로 키보드가 올라와도 입력란과 버튼이 가려지지 않는다
- [ ] 내부 저장소와 SD 카드에서 대소문자만 바꾸는 이름 변경(`a.txt` → `A.txt`)이 된다
- [ ] 같은 폴더에 붙여넣기: 복사는 `- 복사본`으로, 잘라내기는 아무 변화 없이 끝난다
- [ ] 복사한 사진이 갤러리 앱에 보인다
- [ ] 볼륨 간 이동(내부 ↔ SD) 뒤에도 수정한 날짜가 유지된다

### 뒤로 가기와 키보드

- [ ] 기록·선택·열린 메뉴가 없을 때 예측형 뒤로 가기로 홈 화면으로 나간다
- [ ] 하드웨어 키보드 단축키가 뷰어를 닫은 뒤에도 동작한다(Ctrl+C/X/V/A, Delete, F2, F5, Alt+←/→/↑)
- [ ] 검색 상자에 포커스가 있을 때 Alt+←가 동작하고, Backspace·Ctrl+A/C/V/X는 텍스트 편집에 쓰인다
- [ ] 검색 상자에서 한국어 IME로 입력하는 동안(조합 중)에는 검색이 실행되지 않고, 확정하면 실행된다

### 이미지

- [ ] 헤더만 읽어 구분하는 애니메이션 GIF/WebP 확인: 애니메이션은 재생되고, 정지 GIF/WebP는 정지 이미지로 열린다
      (애니메이션이 32 MiB를 넘으면 정지 이미지로 보인다)
- [ ] 큰 사진을 확대하면 디테일이 선명해지고(더 높은 해상도로 다시 디코딩) 메모리가 부족해지지 않는다
- [ ] 썸네일 격자를 빠르게 스크롤하거나 볼륨을 꺼내면 `ThumbnailUtils` 작업이 곧바로 멈춘다

### 동영상·오디오

- [ ] 동영상을 보다가 홈으로 나갔다 돌아오면(`ON_STOP` 이후) `VideoView`가 다시 준비되어 그 위치에서 이어진다
- [ ] 재생 중인 동영상·오디오는 화면을 돌리거나 창 크기를 바꿔도 그 위치에서 계속 재생된다(홈으로 나갔다 오면 멈춘 채로 기다린다)
- [ ] 오디오·동영상을 닫았다가 다시 열어도 재생 컨트롤이 정상이다

### PDF

- [ ] 실제 `ParcelFileDescriptor`/`PdfRenderer` 실패(손상된 파일, 읽을 수 없는 파일)가 "손상된 파일" 안내로 나온다
- [ ] 암호로 보호된 PDF가 Android 15(API 35) 이상에서도 "암호로 보호된 PDF" 안내 + 다른 앱으로 열기로 나온다
- [ ] 확대한 PDF를 한 손가락으로 이동(pan)하고 핀치로 확대/축소하는 느낌이 자연스럽다

### ZIP

- [ ] Windows(한국어)에서 만든 ZIP(CP949 이름, 예: `가.txt`/`각.txt`)을 풀면 이름이 깨지지 않는다
- [ ] 실제 `zip -P`로 만든 암호 ZIP을 풀려고 하면 "손상되었거나 암호로 보호된 ZIP입니다"가 나온다
- [ ] 같은 이름의 항목이 두 개 든 ZIP을 풀면 둘 다 남고 요약에 중복이 표시된다
- [ ] Android 14(API 34) 이상에서 `..`이 든 경로의 ZIP이 "안전하지 않은 경로가 있어 압축을 풀 수 없습니다"로 거부된다
      (`ZipPathValidator`)

### 다른 앱과 시스템 선택기

- [ ] 크롬에서 파일 올리기(`<input type="file">`)를 누르면 선택지에 "파일 탐색기"가 있고, 거기서 고른 사진·PDF가 이름·크기와
      함께 올라간다(`<input type="file" multiple>`이면 고른 파일이 모두)
- [ ] 카카오톡의 파일 첨부에서 "파일 탐색기"로 고른 파일이 전송된다(앱 선택 창에서든 시스템 선택기 옆면에서든)
- [ ] 모든 파일 관리 권한을 주기 전에 다른 앱에서 처음 "파일 탐색기"로 고를 때: 권한 화면 → 설정 → 뒤로 가기로 선택 화면에
      돌아오고, 고른 파일이 그 앱에 간다
- [ ] 그렇게 권한을 받기 전에 시작된 탐색기에서는 선택 화면의 USB 드라이브가 "이 폴더에 접근할 수 없습니다"로만 보이고 다시
      시작을 제안하지 않으며, 탐색기가 다시 시작된 뒤에는 열린다
- [ ] 고르는 도중 화면을 돌려도, 선택 화면을 연 채 홈으로 나가 탐색기 프로세스를 종료하고
      (`adb shell am kill io.github.sakkijarvenpolkka.explorer`) 돌아와 골라도 그 앱이 고른 파일을 받는다
- [ ] USB 드라이브에서 고른 파일을 그 앱이 읽을 수 있다
- [ ] 모든 파일 관리 권한이 없으면 시스템 선택기에 "파일 탐색기"가 없고, 권한을 준 뒤 선택기를 다시 열면 나타나며, 설정에서
      권한을 회수하면(탐색기가 종료됨) 선택기가 다음에 탐색기를 부를 때(최근 화면을 열 때 등) 사라진다
- [ ] 시스템 선택기(다른 앱의 "파일 열기", `ACTION_OPEN_DOCUMENT`)의 옆면에 "파일 탐색기"가 있고, 그 안에 즐겨찾기 폴더
      다음 드라이브가 보이며 검색이 동작한다. 탐색기에서 최근 연 파일은 "파일 탐색기" 안이 아니라 선택기의 "최근" 화면에
      다른 앱의 최근 파일과 함께 보이고, 45일 안에 수정한 파일만 보인다
- [ ] 선택기의 "최근" 화면에서 검색하면 같은 파일이 두 번 나오지 않고, 형식·크기·날짜 칩을 고르면 그에 맞는 항목만 남는다
- [ ] 설정에서 탐색기를 강제 종료한 직후 다른 앱의 선택기에서 "파일 탐색기"를 둘러보고, 검색하고, 저장할 수 있다
- [ ] 선택기가 SD 카드나 USB 드라이브의 폴더를 보여 주는 동안 알림 창에서 그 드라이브를 꺼내면 그 폴더가 다시 읽혀
      선택기의 불러오기 오류가 나온다(꺼낸 드라이브의 항목이 남아 보이지 않는다)
- [ ] 항목이 2만 개쯤인 폴더가 내부 저장소와 USB 드라이브 모두에서 20초 안에 선택기에 나온다(선택기는 20초 넘게 답하지
      않는 공급자를 응답 없음으로 처리한다)
- [ ] 시스템 선택기의 "파일 탐색기"에서 사진·동영상 썸네일이 보인다
- [ ] 메모 앱 등의 "다른 이름으로 저장"(`ACTION_CREATE_DOCUMENT`)으로 "파일 탐색기"의 폴더에 저장하면 그 폴더에 저장한
      내용의 파일이 생긴다(탐색기에서 열어 확인)
- [ ] 폴더 선택(`ACTION_OPEN_DOCUMENT_TREE`)에서 "파일 탐색기"의 맨 위 폴더, 모든 드라이브의 루트(USB 드라이브 포함),
      드라이브마다 맨 위의 `Download`·`Android`는 고를 수 없고, 그 밖의 폴더(`Android/media`, `Documents` 등)는 고를 수 있다
- [ ] 시스템 선택기(또는 폴더 권한을 받은 다른 앱)에서 "파일 탐색기" 안의 파일을 지우면 탐색기의 휴지통에 있고, 원래
      위치로 복원된다
- [ ] `ACTION_OPEN_DOCUMENT`로 파일 하나를 연 앱(폴더 권한 없이 그 파일의 권한만 가진 앱)이 그 파일의 이름을 바꾸고
      (`DocumentsContract.renameDocument`) 돌려받은 새 주소로 다시 열 수 있다
- [ ] 다른 앱이 "파일 탐색기"를 통해 파일을 덮어써 저장한 직후 그 파일의 이름을 바꾸거나 다시 열면 새 내용이 있다
- [ ] 다른 앱이 "파일 탐색기"를 통해 파일을 덮어써 저장하는 도중 설정에서 그 앱을 강제 종료하면 원본이 그대로 남는다
- [ ] 시험용 앱으로 `"w"`/`"wt"` 저장을 닫는 방법마다: 오류 없이 닫으면(`close`) 파일이 새 내용으로 바뀌고,
      `closeWithError`(ERROR), 쓰던 앱의 종료(DEAD), 닫지 않고 버린 파일(LEAKED), `detachFd()`(DETACHED)로 끝나면 원본이
      그대로이며 `.xpart` 임시 파일이 남지 않는다. LEAKED와 DETACHED에서는 쓴 앱이 저장했다고 여길 수 있지만 새 내용은
      버려지는데(파일을 닫지 않는 앱은 저장을 잃는다), 이것이 정해진 동작이다
- [ ] 남은 공간이 거의 없는 드라이브에서 다른 앱이 덮어써 저장하다 공간이 모자라면, 그 앱이 파일을 정상적으로 닫아도
      원본이 그대로 남는다(잘린 내용으로 바뀌지 않는다)
- [ ] FUSE 볼륨(내부 저장소, SD 카드)에서 다른 앱이 덮어써 저장한 직후 기기를 강제로 재부팅하거나 전원이 끊겨도 파일은
      이전 내용이나 새 내용 중 하나이고, 잘린 내용이 되지 않는다(파일과 폴더를 디스크까지 기록)
- [ ] FUSE 볼륨에서 다른 앱이 덮어써 저장한 파일이 MediaStore에(사진이면 갤러리에도) 새 크기와 수정한 날짜로 보인다
      (숨긴 임시 파일이 대상 위로 이름이 바뀐 뒤의 MediaProvider 기록)
- [ ] 갤러리에 있는 사진을 다른 앱이 "파일 탐색기"를 통해 덮어써 저장해도 갤러리에서 같은 항목으로 남는다(MediaStore ID와
      들어 있던 앨범이 그대로이고, 사진이 둘로 늘거나 사라지지 않는다)
